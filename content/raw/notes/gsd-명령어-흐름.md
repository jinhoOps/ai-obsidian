# GSD (Get Shit Done) 프로젝트 관리 워크플로우

전체적인 GSD 워크플로우는 다음과 같은 생명주기로 순환합니다.

> **1. 프로젝트 시작 → 2. 마일스톤 생성 → 3. 페이즈 관리 → 4. 마일스톤 완료 및 클린업 → 5. (반복) 새로운 마일스톤 생성**

---

## 1. 새 프로젝트 시작 및 초기화

### 1단계: 프로젝트 생성
```bash
/gsd-new-project
```
- 프로젝트 이름, 목표, 기술 스택 등을 입력하여 초기 구조를 생성합니다.
- 프로젝트 기본 정보는 `.planning/` 디렉토리에 저장됩니다.

### 2단계: 첫 마일스톤 생성
```bash
/gsd-new-milestone
```
- 프로젝트의 주요 목표를 마일스톤으로 정의합니다.
- AI와의 질의응답을 통해 마일스톤의 범위와 성공 기준을 구체화합니다.

---

## 2. 일상적인 작업 및 페이즈 관리

### 시작하기에 앞서..

```bash
/gsd-progress --next
```
- 무지성으로 하려면 gsd 에게 알아서 다음단계 파악하게 할 수 있습니다.

### 진행 상황 확인
```bash
/gsd-progress
```
- 현재 마일스톤의 완료율, 각 페이즈의 상태, 다음에 수행해야 할 작업을 한눈에 확인합니다. (주로 아침 업무 시작 시 사용)

### 작업 재개 (Context Restoration)
```bash
/gsd-resume-work
```
- 이전 세션이나 어제 하던 작업의 맥락을 복원하고 다음 태스크를 안내받습니다.

### 페이즈 계획 수립
```bash
/gsd-plan-phase
```
- 현재 페이즈의 상세 구현 계획(`PLAN.md`)을 작성합니다.
- 코드베이스를 분석하여 필요한 변경사항을 구체적인 태스크 목록으로 도출합니다.

### 페이즈 실행
```bash
/gsd-execute-phase
```
- 계획서에 따라 실제 구현을 시작합니다. 
- 각 태스크를 순서대로 실행하며 진행 상황을 지속적으로 업데이트합니다.

### 논의 및 문제 해결 (선택)
```bash
/gsd-discuss-phase
```
- 작업 중 막히거나 설계 논의가 필요할 때 AI와 접근 방식에 대해 논의합니다.
- 대안적 구현 방법, 트레이드오프 분석, 위험 요소 점검 등에 활용합니다.

### 페이즈 검증
```bash
/gsd-validate-phase
/gsd-verify-work
```
- 페이즈 완료 후, 계획된 목표가 달성되었는지 검증합니다.
- 단순히 태스크 완료 여부가 아니라, **실제로 기능이 의도대로 동작하는지** 목표 역방향으로 분석하고 확인합니다.

---

## 3. 마일스톤 종료 및 클린업 (정석 워크플로우)

진행 중인 마일스톤을 완벽하게 종료하고 다음 마일스톤으로 넘어가기 위해서는 반드시 아래의 5단계를 순서대로 실행해야 합니다.

### 1단계: 마일스톤 사전 검증 (Audit)
```bash
/gsd-audit-milestone
```
- **하는 일**: 현재 마일스톤의 요구사항이 빠짐없이 잘 구현되었는지, 흐름이 깨진 곳은 없는지 최종 검증합니다.
- **비고**: 만약 이 단계에서 구현 누락이나 버그 등 해결되지 않은 갭(Gap)이 발견되면, 추가 페이즈를 등록하여 해결한 뒤 다시 검증을 진행해야 합니다. 검증이 통과(Passed)되면 2단계로 진행합니다.

### 2단계: 공식 마일스톤 종료 및 아카이빙 (Complete)
```bash
/gsd-complete-milestone
```
- **하는 일**: 마일스톤을 공식적으로 종료 상태로 전환합니다. 
- 로드맵과 요구사항 문서를 완료 처리하여 `.planning/milestones/` 하위로 백업하고, 프로젝트 마스터 문서(`PROJECT.md`)의 버전을 올린 뒤, 해당 버전에 대한 Git 태그(Tag)를 생성합니다.

### 3단계: 물리적 페이즈 폴더 정리 (Cleanup)
```bash
/gsd-cleanup
```
- **하는 일**: `.planning/phases/` 경로에 지저분하게 쌓여 있는 개별 페이즈 폴더들을 아카이브 경로(`.planning/milestones/v{버전}-phases/`)로 깔끔하게 이동시켜 정리합니다. 
- 이를 통해 프로젝트의 폴더 구조와 용량을 쾌적하게 유지하고, 컨텍스트 윈도우 효율을 높입니다.

### 4단계: 교훈 및 패턴 지식 추출 (Extract Learnings)
```bash
/gsd-extract-learnings
```
- **하는 일**: 정리된 페이즈들의 산출물(계획서, 결과 요약서 등)을 분석하여 핵심 의사결정 기록, 새로 알게 된 개발 패턴, 직면했던 문제와 해결책을 추출하여 `LEARNINGS.md`를 작성합니다.
- **후속 작업**: 추출된 지식은 프로젝트의 공유 위키에 연계하여 영구 기억으로 저장합니다.

### 5단계: 새로운 마일스톤 시작 (New Milestone)
```bash
/gsd-new-milestone
```
- **하는 일**: 이전 마일스톤의 정리 작업이 완전히 끝났으므로, 다음 버전을 위한 새로운 요구사항 정의 및 로드맵 설계 단계를 시작합니다.
