# 🏷️ OpenHuman (오픈휴먼)

> **유형**: 엔티티 (Entity)
> **역할**: '기억'과 '로컬 데이터' 중심의 오픈소스 AI 개인 비서 프로젝트
> **주요 리포지토리**: https://github.com/tinyhumansai/openhuman

---

## 📌 정의

**OpenHuman**은 사용자의 다양한 디지털 계정(Gmail, Slack, Notion 등)을 연결하여 얻은 맥락 정보를 로컬 메모리 트리(Memory Tree)로 구축하고 기억하는 오픈소스 AI 에이전트 비서입니다. 에이전트의 콜드 스타트(Cold Start) 문제를 '메모리 우선(Memory-first)' 방식으로 해결하고자 합니다.

---

## ⚙️ 주요 아키텍처 및 모듈

### 1. Composio 커넥터 레이어
* 118개 이상의 서드파티 서비스와 원클릭 OAuth로 연동됩니다.
* 수집된 연동 데이터들은 에이전트에게 **타입이 지정된 도구(typed tool)**로 제공되어 LLM이 직접 행동을 지시할 수 있게 합니다.

### 2. Auto-fetch 동기화 루프
* 20분 간격으로 동작하며 사용자의 조작 없이 새로운 디지털 활동 데이터를 메모리로 긁어옵니다.

### 3. 로컬 메모리 트리 (Memory Tree)
* 수집된 데이터를 마크다운 청크로 변환해 SQLite에 계층형 요약 트리 형태로 저장합니다.
* 사용자가 내용을 확인하고 통제할 수 있도록 동일 데이터를 Obsidian 호환 볼트(`.md` 파일 포맷) 형태로 로컬 머신에 유지합니다.

### 4. TokenJuice (토큰 압축 레이어)
* 웹 스크래핑 결과, HTML 태그, 긴 URL 등에서 무의미한 요소를 지우고 마크다운으로 재가공하여 LLM 토큰 소모량과 대기 시간을 최대 80% 가량 최적화합니다.

---

## ⚖️ 강점 및 한계

### 강점 (Strengths)
* **즉각적인 맥락 형성**: 며칠씩 에이전트가 학습할 필요 없이 계정 연동 직후 전체 지식 베이스를 획득합니다.
* **사용자 주권 확보**: 모든 데이터를 로컬에 수집하며 Obsidian 볼트를 통해 사용자가 AI의 기억을 통제·편집할 수 있습니다.
* **메모리 공유**: `agentmemory` 백엔드 호환성을 지원하여 다른 에이전트(예: [[claude-code]] 등)와 동일한 기억 저장소를 공유할 수 있습니다.

### 한계 (Limitations)
* **하이브리드 오픈소스**: 라이선스는 GNU 오픈소스이지만 OAuth 핸드셰이크, 모델 라우팅, 검색 프록시 등이 기본적으로 OpenHuman 서버를 거치도록 설계되어 있습니다.
* **자가 운영의 난이도**: 완전한 로컬 단독 구동(direct mode)을 시도할 경우, 트리거 웹훅을 직접 호스팅하고 API 키를 별도로 세팅해야 하는 시스템 복잡도가 늘어납니다.
