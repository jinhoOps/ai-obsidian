# Getting started with loops

Claude Code 팀이 공식 분류한 **에이전트 루프(Agentic Loop)**의 정의와 네 가지 계층 구조, 그리고 이를 안정적으로 유지하고 토큰 소모를 방어하기 위한 실무 가이드라인을 다룬 아티클입니다.

## 핵심 내용

### 1. 에이전트 루프의 정의와 의의
* **정의**: 에이전트가 특정 정지 조건(Exit Criteria)을 충족할 때까지 자율적으로 작업 사이클(맥락 수집 -> 수정 -> 테스트 실행 -> 검증)을 반복하는 흐름입니다.
* **의의**: 사람이 매 턴마다 판단하여 다음 프롬프트를 쳐야 했던 기존의 단발성 프롬프트 인터랙션에서 벗어나, 에이전트가 목적 달성을 주도하도록 역할을 위임(Delegation)하는 패러다임의 변화를 의미합니다.

### 2. 에이전트 루프의 4단계 계층화
Claude Code 팀은 에이전트 루프를 트리거 조건, 종료 기준, 사용되는 CLI 프리미티브에 따라 다음과 같이 4가지 칸으로 분류했습니다:

| 단계 | 루프 유형 | 트리거 (Trigger) | 종료 조건 (Stop Criteria) | 주요 프리미티브 / 도구 | 적합한 작업 |
|---|---|---|---|---|---|
| **L4** | **프로액티브 (Proactive)** | 외부 이벤트 / 스케줄 | 각 하위 태스크의 목표 달성 시 | `/schedule`, `/goal`, 오토 모드, 동적 워크플로우 | 버그 리포트 대응, 이슈 분류 등 실시간 사람이 개입하지 않는 연속적 흐름 |
| **L3** | **시간 기반 (Time-based)** | 주기적 시간 간격 (Interval) | 사용자 취소 또는 큐 비워짐 | `/loop`, `/schedule` | Slack 일일 요약, PR 상태 모니터링 및 CI 오류 복구 등 외부 시스템 연동 |
| **L2** | **목표 기반 (Goal-based)** | 사용자의 명령 실행 | 목표 달성 또는 최대 턴 도달 | `/goal` | 정량화 가능한 종료 기준(테스트 100% 통과, 특정 성능 점수 달성 등)이 있는 복잡한 작업 |
| **L1** | **턴 기반 (Turn-based)** | 사용자 프롬프트 | 에이전트 스스로의 판단 | 단발 프롬프트, `SKILL.md` (검증 가이드) | 단발성 탐색 및 간단한 수정 작업 |

### 3. 루프 안정화 및 품질 관리 방안
* **자기 검증(Self-Verification) 설계**: 에이전트가 통과 여부를 스스로 측정할 수 있도록 정량적이고 눈금으로 잴 수 있는 검증 규칙을 `SKILL.md`에 명문화해야 합니다. (예: 브라우저 실행 -> UI 인터랙션 검증 -> 에러 확인 -> 성능 trace 순으로 구체화)
* **독립적인 코드 리뷰**: 메인 에이전트가 편향되거나 자체 합리화하는 것을 막기 위해, 별도의 문맥을 가진 두 번째 에이전트(예: CLI 내장 `/code-review` 또는 GitHub PR Review)에게 코드 리뷰 검증을 맡기는 이중 교차 검증 구조를 설계합니다.
* **깨끗한 코드베이스 유지**: 에이전트는 코드베이스의 기존 패턴과 컨벤션을 모방하므로, 코드의 질이 곧 루프 결과물의 질을 결정합니다.

### 4. 토큰 소모 제어 및 효율화 (Cost Optimization)
* **명확한 목표와 Turn Cap 설정**: 무한 루프나 불필요한 Reasoning 낭비를 방지하기 위해 "5회 시도 후 중단"과 같이 한계를 설정합니다.
* **결정론적 작업의 스크립트화**: Reasoning이 필요하지 않은 형태의 반복(예: 단순 폼 채우기, 포맷 변환 등)은 프롬프트가 아닌 로컬 실행 스크립트로 작성해 에이전트가 실행만 하도록 유도합니다.
* **적정 스케줄 간격 조정**: 외부 상태 감시 시 변화 속도에 맞추어 시간 간격을 적절히 늘립니다.

## 생각 및 메모
* **학습 및 지식 공유 활용**: 이 소스는 사용자가 에이전틱 프레임워크의 **새로운 방법론을 학습**하고, 준비 중인 **AI 지식 공유의 핵심 콘텐츠**로 활용하기 위해 캡처되었습니다.
* **지식 공유 적용 제언**: 에이전트 루프의 4단계 분류(Turn-based, Goal-based, Time-based, Proactive)는 초보자부터 심화 학습자까지 에이전트의 작동 원리를 직관적으로 이해할 수 있는 훌륭한 시각적 장치(테이블 또는 다이어그램)가 됩니다. 특히 `SKILL.md`를 통한 '자기 검증 설계' 예시는 실무적 지식 공유 자료에서 핵심 꿀팁으로 다루기 좋습니다.
