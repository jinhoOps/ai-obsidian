# Hybrid Search (하이브리드 검색)

> **"벡터 기반의 의미(Semantic) 검색과 전통적인 키워드(Keyword) 검색의 강점을 RRF 알고리즘으로 결합하여 검색의 정확도와 맥락 이해도를 극대화하는 하이브리드 정보 인출 기술"**

---

## 1. 개념 설명 (비유)
도서관에서 책을 찾는 두 명의 사서가 있다고 해봅시다.

1. **키워드 사서 (tsvector)**: 이 사서는 아주 꼼꼼해서 책 속에 **'정확한 단어'**가 들어있는지만 찾습니다. 예를 들어 "인공지능 뇌"를 찾으라고 하면 책 표지나 본문에 정확히 '인공지능'과 '뇌'라는 글자가 박힌 책만 골라냅니다. 하지만 "신경망을 활용한 지능형 마인드"처럼 뜻은 같으나 단어가 다른 책은 다 놓쳐버립니다. (높은 정밀도, 낮은 유연성)
2. **의미 사서 (pgvector)**: 이 사서는 단어 글자 자체에는 집착하지 않고 **'의미와 분위기'**를 봅니다. "인공지능 뇌"를 찾으라고 하면 그와 느낌이 비슷한 "인공지능", "딥러닝", "생각하는 컴퓨터" 등의 책들을 뭉텅이로 가져옵니다. 그러나 간혹 엉뚱한 수필집을 집어오기도 하고, 아주 고유한 고유명사나 특정 에러 코드 같은 것은 엉뚱한 벡터 값 때문에 잘 찾지 못합니다. (높은 유연성, 낮은 정확성)

**하이브리드 검색 (Hybrid Search)**은 이 두 사서가 찾은 책 목록을 합친 뒤, 두 사서 모두가 높은 순위로 추천한 책을 맨 앞으로 올리는 **'RRF(상호 순위 결합)'** 규칙을 적용해 가장 완벽한 한 권의 책을 뽑아내는 협업 시스템입니다.

```
                  ┌──────────────────────┐
                  │   사용자 질문 (Query)  │
                  └──────────┬───────────┘
            ┌────────────────┴────────────────┐
            ▼ (의미/맥락)                       ▼ (정확한 키워드)
     [ pgvector 검색 ]                 [ tsvector 검색 ]
   - 뜻이 비슷한 문서 매칭           - 정확한 단어/ID 매칭
   - 예: "지식 비서"                 - 예: "gbrain v0.2.0"
            │                                 │
            └────────────────┬────────────────┘
                             ▼
             [ RRF (Reciprocal Rank Fusion) ]
               두 결과의 순위를 계산하여 병합
                             │
                             ▼
                  ┌──────────────────────┐
                  │   최종 하이브리드 결과   │
                  └──────────────────────┘
```

---

## 2. 정확한 정의 및 메커니즘
하이브리드 검색은 크게 세 가지 축으로 이루어집니다.

| 컴포넌트 | 기술적 구현 예시 | 동작 메커니즘 | 강점 |
|---|---|---|---|
| **밀집 검색 (Dense Search)** | `pgvector` (HNSW 인덱싱) | 텍스트를 다차원 벡터 공간의 좌표로 임베딩하여 **의미적 유사도(Distance)**를 계산 | 동의어 처리, 추상적 질문 이해, 문맥적 검색 |
| **희소 검색 (Sparse Search)** | `tsvector` (BM25, PostgreSQL FTS) | 문서를 토큰화하고 형태소를 분석하여 **정확한 단어의 빈도와 일치 여부**를 계산 | 에러 로그, 고유명사, 특정 버전 코드, 정확한 ID 매칭 |
| **순위 결합 (Rank Fusion)** | **RRF** (Reciprocal Rank Fusion) | 각 검색 엔진이 반환한 문서의 순위(Rank)를 역수($1 / (k + rank)$) 취하여 합산하는 무감독 병합 알고리즘 | 벡터와 키워드의 서로 다른 점수 체계를 표준화하여 공정하게 결합 |

---

## 3. RAG(검색 증강 생성)에서의 왜 중요한가?
AI 에이전트(예: Claude, Cursor, Antigravity CLI)와 마크다운 기반의 지식 베이스를 연결할 때, 하이브리드 검색이 없으면 다음과 같은 한계에 봉착합니다.
1. **단어 미스매치**: 사용자가 "개인 메모 RAG 연동법"이라고 물었을 때, 본문에는 "지식 베이스 에이전트 협업"이라고만 적혀있다면 키워드 검색은 실패합니다.
2. **할루시네이션(환각) 유발**: 벡터 검색만 쓰면 관련 없는 문서를 억지로 가져와 LLM에 컨텍스트로 전달하므로 AI가 거짓 답변을 지어내게 만듭니다.
3. **해결책**: 하이브리드 검색을 쓰면 정확한 기술 스택 명칭(예: `Supabase Storage`, `MIT License`)과 의미적 맥락(예: "Garry Tan의 메모법")을 모두 안전하게 포착하여 최상의 컨텍스트를 공급하고 할루시네이션을 예방할 수 있습니다.
