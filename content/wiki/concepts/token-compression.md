# 💡 Token Compression (토큰 압축)

> **유형**: 개념 (Concept)
> **한 줄 정의**: LLM에 전달되는 원시 텍스트에서 불필요한 노이즈를 제어하고 유의미한 내용만 남겨 비용을 절감하고 응답 속도를 높이는 입력 최적화 기법

---

## 🧠 비유를 통한 이해: 알짜배기 영양분만 추출하는 과일 착즙기

우리가 비타민을 섭취하기 위해 오렌지 100개를 직접 씹어 먹으려면 껍질, 씨앗, 질긴 섬유질까지 모두 소화시켜야 하므로 턱도 아프고 배가 금방 불러 더 먹기 힘듭니다(과도한 HTML 태그, 메타 정보, 긴 URL이 포함된 원시 텍스트를 LLM에 전부 밀어 넣어 발생하는 리소스 소모).

**토큰 압축**은 영양소(핵심 정보)만 온전히 뽑아 한 컵에 담아내는 **착즙기**와 같습니다.
1. 질긴 껍질과 씨앗(HTML 태그, 스타일 시트, 빈 공백 등)은 쓰레기통으로 버립니다.
2. 부피를 많이 차지하는 묶음(장황한 헤더 문구, 중복 API 리스폰스 구조)은 한 줄의 요약으로 압축합니다.
3. 아주 거대한 통나무 같은 것(수백 자에 달하는 트래킹 파라미터가 포함된 긴 URL)은 작은 스티커(단축 링크)로 교체합니다.

이렇게 짜낸 한 컵의 주스(압축된 마크다운 텍스트)를 LLM에 마시게 하면, 훨씬 적은 토큰(식사량)으로도 동일한 정보(영양분)를 신속하게 소화할 수 있어 지연 시간(Latency)과 비용이 크게 절감됩니다.

---

## 📋 정확한 정의

**토큰 압축(Token Compression)**은 대형 언어 모델(LLM)에 텍스트를 주입하기 전에 전처리 레이어에서 정보 밀도(Information Density)를 극대화하는 최적화 프로세스입니다. 

구조적 메타데이터(HTML, XML, JSON 등)나 반복되는 보일러플레이트 텍스트를 파싱하여 순수 텍스트(마크다운 등)로 변환하고, 주요 내용을 요약 또는 중복 제거함으로써 입력 프롬프트의 토큰 수를 줄이는 것을 뜻합니다. 이를 통해 **API 비용 절감**, **Context Window 한계 극복**, **지연 시간(Time-to-First-Token) 감소**라는 세 가지 이점을 얻을 수 있습니다.

---

## 🛠️ 주요 구현 방식 (예: OpenHuman의 TokenJuice 사례)

1. **포맷 변환 및 마크다운 단순화**: HTML 코드를 LLM이 직관적으로 이해할 수 있는 경량 마크다운(Markdown) 형태로 변환하며 스타일이나 미디어 전용 헤더 같은 노이즈를 소거합니다.
2. **참조 요소 축소**: 원문에 반복해서 나타나는 수많은 링크와 트래킹 인자가 붙은 긴 URL을 단순한 짧은 식별자나 내부 단축 링크로 변환합니다.
3. **CJK 및 이모지 단위 보존**: 단순히 바이트나 문자열을 기계적으로 잘랐을 때 한글, 한자, 일어(CJK)나 이모지 등의 멀티바이트 글자가 깨지는 현상을 방지하기 위해 자소/문자(Grapheme) 단위의 정교한 경계선 슬라이싱을 적용합니다.
4. **LLM 기반 선별적 요약**: 단순한 룰 베이스 필터링이 불가능할 경우, 저비용 로컬 모델(Ollama 등)을 이용해 정보를 미리 1차 요약하여 메인 모델에 주입합니다.

---

## ⚖️ 의의와 가치

* **비용 절감**: LLM API 가격 책정은 입출력 토큰 단가 기준이므로, 프롬프트를 압축하여 전달하면 직접적으로 비용을 최대 50~80% 아낄 수 있습니다.
* **추론 속도 향상**: LLM은 입력 토큰을 평가(Prefill Phase)하는 데에 시간이 소요되므로, 토큰이 압축될수록 응답이 처음 출력될 때까지의 대기 시간(TTFT)이 단축됩니다.
* **환각(Hallucination) 감소**: 프롬프트 내부의 무의미한 노이즈가 제거되어 LLM이 핵심 지시사항과 본문 맥락에 온전히 집중할 수 있도록 유도합니다.
